## Exact identity and stopped semantics

The old `readonlyChecks` accepted caller-selected argv and expected exit/output hashes. An expected observation alone does not prove a writer is stopped. That interface is removed; old manifests fail closed.

`window.writers` now lists unique reviewed writer IDs, manager kinds, exact manager identities, affected database sides and approved probe executable digests. A separate `writerInventory` control file pins the canonical inventory, host/boot, both database paths/digests and responsibility record. The existing full execution-approval projection binds this entire window. Jenn uses the independently installed approved inventory, never a replacement list supplied by a remote result. Inventory completeness must be established by technical review of the actual deployment before an execution package can be approved; the tool does not discover all possible writers.

Every declared item must be checked. Runtime and legacy-helper roles, both database sides, helper program identity, and unique IDs/targets are required. Arbitrary `pgrep`, `systemctl is-active`, user-specified argv or opaque success digests are no longer admissible.

Supported adapters are deliberately bounded:

- **Systemd:** an exact `.service` identity with a fixed, root-custodied program path and digest. This version supports only the literal unit profile generated by `unit_bytes()` (`Type=simple`, one absolute `ExecStart` without arguments, `Restart=no`, `KillMode=control-group`) at `/usr/local/lib/systemd/system/<unit>`. Its full bytes are approved. Higher-priority competing unit files are rejected. A root-custodied runtime mask at `/run/systemd/system/<unit>` must point to `/dev/null`; complete parent and link identities are checked before/after the probe. Actual manager output must identify that unit and mask, report inactive/dead, no main/control PID, no drop-ins, `Restart=no`, and `NeedDaemonReload=no`. `TasksCurrent=[not set]` is accepted only with empty `ControlGroup` and an independently observed absence of that unit's canonical cgroup in the cgroup v2 hierarchy. An existing cgroup, even if apparently empty, rejects.
- **Docker runtime writer:** only the local root-custodied `/run/docker.sock`, a full container ID and an approved image/command/mount configuration digest. Structured output must report created/exited, no running/paused/restarting/dead flag, PID zero, no state error, and restart policy `no`. Approved database sides must be covered by the reported mounts. Unknown identity, configuration or state rejects. Docker helper control is not supported in this revision.
- **Legacy helper:** must be the actual program in the supported systemd profile; its entrypoint path and digest must match the `legacyHelper` control. A text file saying “disabled”, an unrelated stopped unit, or a string-based process search is insufficient. Unmanaged helpers, alternate entry paths, general unit profiles, and other controls outside this adapter's supported model remain BLOCKED. The tool does not install units, mask services, move helpers into managers, or infer permission to adapt production.

Systemd/Docker probe paths are fixed; their approved bytes and complete root parent custody are checked. Probes receive the fixed minimal environment, with no ambient Docker context or manager overrides. Per-probe streams are bounded to 8 KiB, the item count to 16, and failures/timeouts/unknown results reject.

## Raw evidence and independent acceptance

`writersBefore` and `writersAfter` contain every item's exact command, executable pin, environment, exit status, raw stdout/stderr and digests, manager guard and parsed state. Jenn verifies exact fields and full inventory coverage, then independently reparses raw state and guard semantics. Missing/extra items, altered targets, incomplete output, active state or unsupported helper controls reject. Before/after writer evidence must match. These are mandatory in the R2 receipt; historical R2 receipts missing them are not upgraded.

The host administrator remains responsible for complete registered entry coverage and for preventing direct invocation, new instances, unmasking, socket/daemon replacement, or other configuration changes throughout the window and required evidence-use interval. A stopped observation does not prove indefinite future quiescence. The masks in this experiment were created only inside the disposable guest, never on production or Jenn's host.
