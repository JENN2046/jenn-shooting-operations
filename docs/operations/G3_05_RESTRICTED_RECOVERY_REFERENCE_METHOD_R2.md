## 1. 唯一拟议变化及其代价

现行 R1 witness 对任何 `2/2` 输入在 SQLite 解释前返回 `WAL_CHECKPOINT_COMPLETENESS_UNPROVEN`。固定 Schema6→10 重建对账通过，不会消除这个拒绝原因：既无法独立证明原停写约束覆盖了 Schema6 捕获之前到 Schema10 保存完成的有限窗口，也无法证明该历史范围内所有已提交 WAL 状态均已纳入固定捕获状态或 checkpoint 到固定 Schema10 main。后一个命题仍为 `NOT_PROVEN`。

本方法的**唯一拟议例外**是：仅对第 3 节固定档案及经正式完整摘要绑定的 preserved，允许以“已验证的捕获状态及其迁移结果”承担未来 G3 治理采纳的受限恢复参照责任，尽管原窗口 writer 覆盖和历史 WAL 提交完整纳入 main 均未证明。两项相关缺口及其可能漏掉已提交数据的风险，明确属于这一个参照资格例外；不是先承诺 WAL 完整性已证明，再放宽格式检查。经独立技术审查和 Owner 精确批准后，仅在新的 R2 限定路径中，不再让这两项历史缺口单独否决本案固定参照资格。

**代价：不能排除已提交但未被固定 Schema6 main/WAL 捕获的状态，也不能排除原历史 Schema10 WAL 中存在已提交但尚未 checkpoint、且未被 Schema10 main 归档包含的状态。** 固定输入重建相符不能消除这些可能性，也不证明实际发生了数据丢失。本方法不能恢复可能遗漏的数据。任何后续接受均不得表述为“历史 WAL 提交已全部进入 main”“完整恢复了该历史时刻所有应有业务数据”“已证明原捕获期间没有其他写入”或“原切换合法”。

这是一项版本化证据标准变化，不是把未知事实证明为真，也不是对一般 WAL `2/2` 文件的兼容性放宽。它只支持既有 Schema11 的未来治理评价，不改变业务需求、不替换生产数据、不指定另一物理基线。

### 1.1 重建证明与通用拒绝门的关系

固定重建验证的是：SQLite 从第 3 节精确 Schema6 main/WAL 字节解释出的可见状态，经原迁移 7–10 后，与固定 Schema10 main 在已执行的 40 表语义比较范围内相符，仅有事先声明的四个迁移时间字段例外。已归档 WAL 中被 SQLite 纳入该可见状态、并在迁移后保留于被比较状态的效果，包含在这个对账结论中；这不是逐帧、逐事务的历史提交清单，不能据此声称每个历史 WAL 提交均已进入 main。

因此，重建只能证明**所捕获状态的重建一致性**，不能证明档案完整捕获了原库所有已提交事务，不能证明固定 Schema10 main 的历史 checkpoint 完整性，也不能用新重建的 close/reopen 倒推原执行窗口已完成 checkpoint。无 sidecar、`integrity_check=ok`、`immutable=1` 或当前完整字节摘要各自成立，均不提供该历史完整性证明。SQLite 的提交与 checkpoint 是不同操作，参见[官方 WAL 说明](https://www.sqlite.org/wal.html#how_wal_works)。

| 路线 | 必须保持的裁定 |
|---|---|
| 原 R1 witness / R1 回执路径 | 所有 `2/2` 继续以 `WAL_CHECKPOINT_COMPLETENESS_UNPROVEN` 拒绝，在 SQLite 解释前停止；不能因 R2 方法存在而改变 R1 行为。 |
| 尚未获得精确 R2 方法批准，或固定档案/当前对象/完整独立证明链任一不匹配 | `2/2` 仍拒绝，不能先作通用 SQLite 解释后补证；调用者自选材料与摘要相互匹配不构成批准。 |
| 后续经批准并验证的 R2 限定路径 | 仅 preserved `2/2`、active `1/1` 及第 4 节全部条件满足时，才可评价这个固定参照；资格依据是明确获准的受限例外，而非声称 `WAL_CHECKPOINT_COMPLETENESS_UNPROVEN` 所指事实已被证明。 |
| 任意其他 `2/2`、即便没有 sidecar 且 integrity 检查通过 | 不属于本案例外，仍拒绝；不得复用本案摘要、成功状态或 Owner 风险接受，建立一般 `2/2` 放行。 |

## 4. 受限参照资格的必要条件

以下条件全部满足后，新的受限参照资格才可进入生产 E3 评价；单有本方法批准不满足这些条件。

2. **旧证据适用性。** 原重建回执及其认证 SSH、退出码、审批、源码和独立存证记录通过只读回放；状态须为有限补证成功，三个历史资格布尔值 `productionAdmission / historicalCoverageProven / livePreservedBound` 仍为 false。任一真实记录不完整或不能绑定，停止。
3. **当前对象绑定。** 新的正式窗口将当前 preserved 的原 FD、身份和完整摘要绑定到第 3 节 Schema10 main；当前 active 也绑定到精确生产包的预期对象。不能只检查 inode/大小，不能运行时把观察到的新摘要变成预期值。两个目标必须都是 `nlink=1` 的普通文件，`(device, inode)` 二元组不同；逐级父链和 leaf 禁止符号链接，固定 FD 与路径在前后复核中必须指向同一原对象。两个目标的 `-wal`、`-shm`、`-journal` 路径必须全部不存在，包含空文件、目录、普通链接及悬空链接在内的任何存在状态都拒绝；不能通过解释“无用”“旧文件”而接受，也不删除它们继续执行。只读解释前后均须检查，检查失败或有漂移即停止。Schema6 原历史归档中已登记的 WAL/SHM 是已执行重建的输入，不属于这里的当前两目标旁文件。preserved 格式为 `2/2`、active 为 `1/1`；其他组合不属此方法。
