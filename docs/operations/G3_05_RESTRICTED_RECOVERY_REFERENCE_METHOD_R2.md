## 1. 唯一拟议变化及其代价

现行证据路线尚不能接受 preserved `2/2`：固定档案虽然已真实重建对账通过，但无法独立证明原停写约束覆盖了 Schema6 捕获之前到 Schema10 保存完成的有限窗口。

本方法提议：对第 3 节的固定档案，允许以“已验证的捕获状态及其迁移结果”作为未来 G3 治理采纳的受限恢复参照；原窗口 writer 覆盖缺口作为显式保留的不确定性，不再单独否决该参照资格。此变化必须经独立技术审查和 Owner 对本方法精确版本的批准才成立。

**代价：不能排除存在未被档案包含的历史业务提交。** 因而任何后续接受均不得表述为“完整恢复了该历史时刻所有应有业务数据”“已证明原捕获期间没有其他写入”或“原切换合法”。本方法也不能恢复可能遗漏的数据。

这是一项版本化证据标准变化，不是把未知事实证明为真，也不是对一般 WAL `2/2` 文件的兼容性放宽。它只支持既有 Schema11 的未来治理评价，不改变业务需求、不替换生产数据、不指定另一物理基线。

## 4. 受限参照资格的必要条件

以下条件全部满足后，新的受限参照资格才可进入生产 E3 评价；单有本方法批准不满足这些条件。

1. **权威来源。** Jenn 从独立保存的 Owner 精确批准记录和冻结的 R2 合同生成受信批准清单，绑定本方法摘要及第 3 节完整引用链。调用者的 expected 参数必须与清单固定值相同；证明文件和调用者自带摘要相互一致不足以接受。独立审查文本也不能只靠状态词或摘要自行取得权威，必须能从 Jenn 存证中的真实复审记录验证。
2. **旧证据适用性。** 原重建回执及其认证 SSH、退出码、审批、源码和独立存证记录通过只读回放；状态须为有限补证成功，三个历史资格布尔值 `productionAdmission / historicalCoverageProven / livePreservedBound` 仍为 false。任一真实记录不完整或不能绑定，停止。
3. **当前对象绑定。** 新的正式窗口将当前 preserved 的原 FD、身份和完整摘要绑定到第 3 节 Schema10 main；当前 active 也绑定到精确生产包的预期对象。不能只检查 inode/大小，不能运行时把观察到的新摘要变成预期值。两个目标必须都是 `nlink=1` 的普通文件，`(device, inode)` 二元组不同；逐级父链和 leaf 禁止符号链接，固定 FD 与路径在前后复核中必须指向同一原对象。两个目标的 `-wal`、`-shm`、`-journal` 路径必须全部不存在，包含空文件、目录、普通链接及悬空链接在内的任何存在状态都拒绝；不能通过解释“无用”“旧文件”而接受，也不删除它们继续执行。只读解释前后均须检查，检查失败或有漂移即停止。Schema6 原历史归档中已登记的 WAL/SHM 是已执行重建的输入，不属于这里的当前两目标旁文件。preserved 格式为 `2/2`、active 为 `1/1`；其他组合不属此方法。
4. **当前保护和来源。** 双文件、完整父链及实际 writer 受到已接受责任和技术措施约束，正式 SSH、一次性挑战、代码/运行时、实例/boot 及 Jenn 存证全部匹配精确包；失败或漂移停止准入。

## 5. 时间、保护与结果语义

历史重建回执仅作为静态证据按批准摘要引用，不能冒充新鲜生产观测。新的 E2 挑战从签发起 300 秒，先耐久消费再传输；接收完成及最终自动接受都须在墙钟和单调时钟截止点内。

超过期限的记录仍可审计其当时结果，不得用作新的实时准入。持续 immutable 不自动延长挑战期限；本方法不授予跨阶段有效期，G3-06 或后续 claim 须按各自精确包取得新鲜验证。不能因新取证失败而回写旧接受状态。

新的 G3-05 结果必须分开表达：

- 固定档案重建关系：引用原 `PASS`，不篡改原回执。
- 原捕获窗口 writer 覆盖：永久保留 `NOT_PROVEN`；Owner 对剩余不确定性的批准另列。
- 当前 preserved 绑定、当前 E1/E2/E3：由新真实证据分别裁定，未执行前为 `NOT_PROVEN`。
- G3-05 若最终通过，只能表示“按获准 R2 受限方法，生产证据被独立接受”；不能表示历史覆盖已证明或治理采纳已完成。

任何部分保护成功都保留已落实的保护。UNKNOWN 不自动重试，writer 和服务保持关闭。保护及父链责任持续到后续证据使用和所需终验完成，或 Owner 单独批准退出；维护、重启、权限/身份变化时停止证据使用并重新核验。
