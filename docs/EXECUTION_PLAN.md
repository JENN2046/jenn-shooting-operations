# 执行计划

## 已锁定边界

- VCP 工作台：`jenn-shooting-planner`
- 云端服务：本项目独立承载
- 云端事实源：SQLite
- VCPChat：唯一排班修改工作台
- 手机端：需求提报与排班查看
- 群晖：后续只接收备份，不参与在线运行

## 阶段与验收门

### Phase 1：现状冻结

状态：`PASS`

- 识别当前 `products`、`tasks`、`sessions`、`view`、`monthAnchor`。
- 不修改现有 `data.json`。
- 用只读校验器确认当前数据可映射到 v1 契约。

验收：校验器对当前工作台数据返回 `PASS`。

### Phase 2：契约冻结

状态：`PASS`

- 冻结排班快照、需求提报、角色权限、版本冲突与幂等规则。
- UI 偏好 `view`、`monthAnchor` 保留在本机，不进入云端事实源。
- 保留工作台现有字段名，避免第一次接入时做高风险重写。

验收：Schema 可解析；合成 fixture 和当前工作台数据均通过校验；非法数据失败关闭。

### Phase 3：本地服务

状态：`PASS_LOCAL`

- Node.js API 与 SQLite。
- `/board`、`/submit`、`/api/v1/snapshot`、需求写入和排班写入。
- 默认仅监听 loopback；未配置鉴权时禁止修改接口。
- Dockerfile、Compose、健康检查、备份命令和测试。

验收：本地自动化测试通过，不访问腾讯云。

### Phase 4：VCP 受控同步适配器

状态：`PASS_CODE_AND_FIXTURE`

- 同步逻辑放在 VCP 主进程可信边界，不让图表沙箱直接访问外网。
- 拉取云端新需求并合并到待拍池。
- 使用 revision 和 `If-Match` 防止覆盖他人修改。
- 使用 `operationId` 保证重试不重复写入。
- 断网时保留本地镜像和待同步队列。

验收：提交、排班、冲突、断网、恢复、重复重试均通过 fixture 测试。

### Phase 5：部署前预检

状态：`READY_FOR_PREFLIGHT_REVIEW`

- 生成不含秘密值的部署清单。
- 检查端口、磁盘、容器命名、卷路径、回滚和备份恢复步骤。
- 此阶段不上传、不启动、不改安全组、不改生产配置。

验收：本地构建与容器测试通过，并形成明确回滚点。

### Phase 6：腾讯云部署

状态：`BLOCKED_BY_PRODUCTION_DEPLOYMENT_GATE`

这是独立的生产部署门。只有得到 Jenn 对具体部署动作的当前明确授权后才执行。

### Phase 7：群晖备份

云端数据库定时生成加密备份；群晖仅保存副本。群晖离线不影响在线服务。

## 停止条件

- 发现现有工作台数据无法无损映射；
- 需要读取秘密值或活动生产配置；
- 需要改安全组、域名、证书、生产环境变量或启动公网服务；
- 验证失败且无法在当前安全边界内修复；
- 可能覆盖 Jenn 的现有改动。
