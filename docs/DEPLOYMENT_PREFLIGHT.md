# 腾讯云部署前检清单

状态：本地实现已完成；生产部署未执行。

## 本地证据

- 当前 VCP 工作台数据可映射到 v1 契约。
- 服务权限、幂等、版本冲突和非法快照均有自动化测试。
- VCP 同步客户端已与真实本地 HTTP 服务完成拉取、写入、再拉取闭环。
- 浏览器已验证需求提交后进入待排池。
- 图片与附件上传已覆盖类型白名单、文件签名、单文件数量与总容量限制。
- 本机没有 Docker CLI，因此镜像构建尚未在本机验证。

## 部署目标约束

- 使用现有腾讯云 Ubuntu 实例。
- 使用独立容器名、独立数据卷和独立反向代理路径。
- 应用容器只暴露给服务器本机反向代理，不直接开放应用端口到公网。
- 公网只保留 HTTPS；HTTP 仅用于跳转。
- 不读取或改动现有容器的环境变量、数据库或卷。
- 部署前再次确认磁盘余量、端口、容器名和反向代理路由没有冲突。

## 必须在部署时生成的秘密值

- viewer token
- submitter token
- scheduler token
- administrator token

四个值必须独立随机生成，只写入服务器受限配置，不进入 Git、聊天记录、
部署文档或命令输出。

## 部署动作

以下动作属于生产部署门，尚未执行：

1. 在服务器创建独立应用目录与持久化卷。
2. 上传经过检查的源代码或构建上下文。
3. 在服务器生成并安装四类 Token。
4. 构建镜像并启动容器。
5. 验证容器健康检查和本机回环访问。
6. 配置反向代理路径与 HTTPS。
7. 调整安全组或防火墙（仅在确有需要时）。
8. 导入现有工作台数据作为初始版本。
9. 在 VCPChat 中启用服务地址和 scheduler token。
10. 完成手机提报、工作台排班、看板更新和回滚演练。

## 回滚点

- 部署前不接管任何现有域名或路由。
- 新容器、新卷和新反向代理片段保持独立。
- 回滚时先移除新路由，再停止新容器；不删除数据卷。
- VCPChat 未启用云配置时继续使用现有本地数据文件与 localStorage 镜像。

## 已知后续维护项

未提交成功的临时上传会保留元数据。生产启用前需要增加“只清理超过保留期且未绑定任务”的维护命令，并先用 dry-run 验证；不得删除已经绑定到任务的图片或附件。

## 部署授权边界

执行上传、生成生产 Token、启动容器、修改反向代理或安全组之前，需要 Jenn
对本清单所列生产部署动作给出当前明确授权。
